# Secrets handling

## Where secrets live

- **In CI**: GitHub Actions encrypted secrets, scoped to the `production`
  environment where possible so a workflow run against a feature branch
  cannot read them at all — only a run against a protected environment can.
- **On the droplet**: nothing long-lived. The app reads secrets from
  environment variables injected at deploy time by the CI job; none are
  baked into the image, written to a file that survives a redeploy, or
  committed anywhere, including as an "example" file with real values.
- **Terraform state**: the S3 backend is encrypted at rest and access-logged;
  DynamoDB provides state locking so two concurrent `apply` runs can't
  corrupt each other. Origin TLS private keys generated by the
  `cloudflare-dns` module are marked `sensitive` in Terraform outputs, which
  keeps them out of `plan`/`apply` console output but does **not** encrypt
  them in state — treat state as a secret in its own right.

## Rotation

- DigitalOcean API token and Cloudflare API token: rotated quarterly or
  immediately on suspected exposure. Because `validateSecrets` (see
  `src/secrets/validate.ts`) checks shape and length at process start, a
  rotated token that's the wrong shape (truncated paste, wrong token type)
  fails loudly at deploy time instead of silently at first API call.
- SSH keys: no shared keys. Each engineer's own key is added to the DO
  account and referenced by fingerprint in `terraform.tfvars`; revoking one
  person's access is removing one fingerprint and re-applying, not rotating
  a shared credential everyone else also has to pick up.

## What never happens

- No secret is ever logged. `redact()` exists for the one legitimate
  exception: confirming *which* secret rotated without printing it.
- No secret reaches a git history, including in a "temporary" commit later
  amended away — `gitleaks` runs on every push in CI specifically to catch
  this before a maintainer has to explain why an old commit needs purging.
- No password-based SSH, anywhere, per the cloud-init hardening in the
  `digitalocean-app` module.
